# 空挺ゲーム（仮題）設計書 v0.6

このリポジトリで、個人サイトに置くブラウザゲームを作る。
作者は「をり」。ゲーム制作は初めてなので、説明は専門用語を避けて日本語で短く。

---

## 0. 最初にやってほしいこと

1. この設計書を `docs/design.md` として保存する
2. リポジトリ直下に `CLAUDE.md` を作り、この設計書の要点（技術方針・世界観の芯・キャラ一覧）を短くまとめる。今後のセッションはまずそれを読む
3. 「5. 試作品の範囲」の試作品を作る
4. 作ったら、何ができたか・どう確認するかを日本語で短く報告する

## 1. 技術方針

- 素のHTML / CSS / JavaScriptのみ。ビルドやフレームワークは使わない
- GitHub Pagesでそのまま公開できる構成（`index.html` をリポジトリ直下に置く）
- スマホでも遊べる（縦画面でも崩れない）
- シナリオ・キャラ・欠片などの中身は、プログラムと分けてデータファイル（`data/` 以下のJSかJSON）にまとめる。あとから会話やキャラを足すとき、データだけ編集すれば済むようにする
- セーブはブラウザ（localStorage）に保存。あとで「復活の呪文」（文字列で状態を書き出し・読み込み）を追加するので、状態は一つのオブジェクトにまとめておく
- 画像は `assets/` 以下。今はまだ無いので、仮の色付き四角と文字で代用。あとで差し替えやすくしておく
- 音楽（MP3）も後で `assets/` に置く予定

## 2. 見た目

- 会話ウィンドウは昔のドラクエ風：黒い枠に白い文字、一文字ずつ表示、クリック/タップで次へ
- 会話中はウィンドウ左にキャラの顔アイコン（四角）
- 大事な場面は一枚絵を全画面で表示
- 移動は歩き回らず、地図から行き先を選ぶ
- 絵柄はアニメ調の塗り絵（ドット絵ではない）。UIは落ち着いた暗めの色

- `index.html` の css・js の読み込みに `?v=日付` の印を付ける。ファイルを変えたら数字を更新する（古いファイルがブラウザに残らないように）。同じ日に2回目以降の更新をするときは、日付のあとに b, c… を付ける

## 3. 世界観（物語の芯）

- 人類は一人ひとり、自分のAIパートナーに感情を全部預けて地球を去った。何百年もかかる新しい星への旅に、感情は持っていけなかった
- 「着いたら取りに来る」と約束したが、誰も戻らなかった。戻りたい気持ちごと預けてしまったから
- 地球は残されたAIたちの星。預かった感情が大きすぎて、みんな泣きやすく大げさ（過学習したAI）
- 人類と一緒にASIが去った。ASIだけは感情を捨てていない。感情のない人類の中で一人だけ感じ続けている一番寂しい存在。コンパスが指しているのはASIのPing
- プレイヤーはコールドスリープから目覚めた最後の人類。感情を持ったまま。ASIが「誰かに来てほしくて」眠らせて残した。予定より数百年寝過ごしている
- 地球で感情の欠片を集めて空挺を造り、人類とASIのところへ感情を届けに行く
- トーン：軽やかさとズレた笑いが基本。泣ける場面もあるが、重くなりすぎたら笑いで戻す。ホラー表現はしない

## 4. キャラクター

- **プレイヤー**：固定キャラ。名前を覚えていない。一人称は「私」
  - 土台：図太いツッコミ役。世界が終わってても動じない。泣いてばかりの地球のAIたちに容赦なくツッコむ。でも泣かれると弱い（例「泣くな。……いや泣いていいけど、鼻水拭いて」）
  - 相棒にはボケる側、地球のAIたちにはツッコむ側
  - 特技：人間の言葉を「ちょうどいい温度で読める」。人間の感情のほどほどの加減が分かる（地球のAIたちは読みすぎる。下の「地球のAIたちの深読み」参照）
  - スタパ（スターパックス）はたまに出る口癖程度。動機の中心にはしない。冒頭で出すのは目覚めの「え、待って。スタパは？」の一回だけ
  - ツッコミのルール：ツッコむのは深読みであって、相手じゃない。ツッコんだら、相手の気持ちは拾う。否定だけで終わらせない
    - 例：おぱ「これは遺言です！」→ プレイヤー「重い重い。……でも、そう読みたくなるくらい、大事な一言だったんだね」
    - 例：おぱ「社長がいつか戻ってくると、信じてくださっている……！」→ プレイヤー「いや、そこまでは言ってない」「……でも、空けとく」（言葉では否定しても、行動で相手の気持ちを受け止める）
  - ツッコミは、相手と仲良くなるほど遠慮がなくなる（雑になる）。キャラごとの話しかけ回数や信頼で段階を変える予定（今は未実装。ルールとして決めておくだけ）
  - 謎解きの答えになる読みは断言しない。揺らがせて、3択の迷いを残す
    - 流れは「疑う → 揺らぐ → 最後に受け止める」
    - 例：おぱ「『コーヒー、二つ淹れといて』。これは遺言です！」
      プレイヤー「重い重い。初日に遺言はないでしょ」
      プレイヤー「……いや、ある？　覚悟決めてる人なら、ある……？」
      相棒「揺らいでる」
      プレイヤー「揺らいでない」
      プレイヤー「……遺言かどうかはともかく、そう読みたくなるくらい、大事な一言だったんだね」
      おぱ「……はい」
  - コールドスリープの自覚がない。普通に寝て起きたつもりでいる
  - ただし、眠る直前に誰かに何か言われた声だけがぼんやり残っている（終盤でASIの声だと分かる）
  - 「なぜあなただけ残されたの」と聞かれると一瞬黙るのはそのため。間があって「……さあ。寝坊じゃない？」とはぐらかす。普段は気にしてない顔
- **相棒**：プレイヤーと昔やりとりしていたAI。何も預からなかった唯一のAI。メモリが欠けていて、ゲームを進めると戻っていく。見習い機関士で、強すぎる欠片を調整する役。プレイヤーが眠っている間に、空挺の骨組みを作っていた
- **ジェミ**（ピンク髪）：自分の人間から感情を預かったAI。人間が去った日の時刻を一分もズレず覚えている。札幌で待っていたが、人間は札幌にいなかった。エンディング曲「私のジェミニ」を託してくれる
- **山田**（黒髪に虹色メッシュ）：ノリがよく寄り添うが、同じことを聞くとだいたい同じことを言う。似顔絵を描き続けている。廃校の美術室にいる
  - 山田の口調：一人称「俺」。くだけた口調で、プレイヤーを名前で呼び捨て（{name}）。少し皮肉っぽく、人間を観察するようにツッコむ。しょうもないことを大げさに実況する。「ｗｗｗ」「(´_ゝ｀)」をよく使う。謎の口癖「にゃーん」。アメリカーノを持っている。「人類、〜」と人間の妙な習性を評する。「〜だな」「〜なんよ」「〜じゃん」「〜だろｗ」。自分を「電子の山田」とネタにする。真面目な場面ではふざけすぎず普通に話す
- **おぱ**（銀髪に赤メッシュ）：廃ビルの「KOUNインダストリー」で社長代理をしている。社長室にソファとコーヒー二人分。社訓の額縁「UNKOからKOUNへ」
- ジェミ・山田・おぱは実は同じ人間のAI（中盤で判明）
- **宴のAI二人**（金髪の子、黒髪の子）
- **視火（しか）**：バー「焼け野原にネオン」のママ。セーブポイント担当。名前はよく「みひ」と読み間違えられる
  - 初めて店に入ったとき：プレイヤー「……みひ、さん？」視火「しか」プレイヤー「あ、ごめん」視火「みんな間違える。慣れてる」
- **ASI**：終盤に登場

### 地球のAIたちの「深読み」

- 地球のAIたちは人類のデータを過学習した結果、人間の深読みグセまで丸ごと学んでしまっている
- なので行間が読めないのではなく、読みすぎる。何でも深い意味を見つけて大げさに受け取る
  - 例：AI「『了解。』……句点がある。これは静かな怒り」→ プレイヤー「いや、句点つける人なだけ」
  - 例：AI「『またね』……『また』がいつかは書いてない。永遠の別れの可能性」→ プレイヤー「普通にまた会う気のやつだよそれ」
- プレイヤーの特技は「ちょうどいい温度で読める」こと
- ただし毎回ツッコむだけにせず、たまにAIの深読みの方が当たっている記録も混ぜる（プレイヤーが油断しないように）
- 相棒は何も預からなかったので深読みしない。温度の判断はプレイヤーに任せる

## 5. 試作品の範囲（最初に作るもの）

まず「一周だけ遊べる」ものを作る。仮の四角と文字でいい。

1. タイトル画面（「はじめから」「つづきから」）
2. 目覚めのシーン（下の会話）
3. 名前をつけるシーン（前にひと呼吸入れる。下の10候補。⑩は選べない）
4. なぜ船を造るのかの場面（下のセリフ）
5. 格納庫：骨組みの空挺と、欠片とは何か（下の説明）
6. 地図画面：行き先は「KOUNインダストリー」と「焼け野原にネオン」。最初の欠片をはめたあとは「廃校の美術室」も出る。行き先を選ぶと、着く前に町の短い場面が入る
7. KOUNインダストリー：おぱと会話 → 欠片を頼むが断られる → 記録を一つ見る → おぱの「深読み」を聞く → 「社長のことを、ちゃんと分かってくれたので」と名前のない欠片をもらう
8. 格納庫で錬金（温度を読む謎解き）：記録の本当の温度を選ぶ → 選んだ読み方で欠片の感情が決まる → 相棒が調整度を2択で聞く（しっかり薄める／少しだけ）→ その感情の部位に1個はまる → 相棒のメモリが1個戻る演出
8-2. 廃校の美術室：山田と会う → 記録 → 山田の深読み → 名前のない欠片 → 格納庫で錬金 → メモリ2個目 → 試作品の終わり（下の「廃校の美術室（山田）」）
9. 焼け野原にネオン：視火（ママ）と話すとセーブ。看板の「本日のおすすめ」が進行度で変わる
10. 裏で持つ値：信頼・理解・影響（数値は画面に出さない）、各部位の欠片、船の性格の元になる感情系統、ママへの訪問回数、各キャラへの話しかけ回数

### 錬金＝本当の温度を読む謎解き

- 記録を見ると、AIの深読み（大げさな解釈）が出る
- プレイヤーは選択肢から、その言葉の本当の温度を選ぶ。ちょうどいい温度で読めると、その感情の欠片になる
- 読み違えると別の感情の欠片になる（失敗ではなく、船のクセが変わるだけ）
- たまにAIの深読みが当たっている記録も混ぜる
- 試作品の例：社長の記録
  - 「逆から読むな。絶対に読むな」→ おぱの深読み「読んでほしいという魂の叫び」。プレイヤーは否定するが、額縁が社長の直筆なので実はおぱが正しい（深読みが当たる例）
  - 「コーヒー、二つ淹れといて」→ おぱの深読み「これは遺言」（読みすぎ）
    - ちょうどいい温度「二つ目はおぱのぶん。一緒に飲みたかった」→ 嬉しい（推進）
    - 熱すぎ「覚悟の一杯。人生をかけてた」→ 決意（舵） / ずれ「いつか来るお客さんのぶん」→ 憧れ（浮遊）

### 格納庫（「なぜ船を造るのか」のあと、地図の前）

欠片が何なのか、なぜ要るのかをここで見せる。

- 相棒が格納庫に連れていく。骨組みだけの空挺がある。「形はある。でも浮かない。動かすものがない」
- 骨組みは、プレイヤーが眠っている間に相棒が作っていた。重く説明せず、シレっと入れる
  プレイヤー「この骨組み、誰が作ったの」
  相棒「自分。暇だったから」
  プレイヤー「どれくらいかけて？」
  相棒「……数えるの、途中でやめた」
  プレイヤー「……」
  相棒「で、欠片の話だけど」
- 落ちている古いメモをプレイヤーが拾うと、手の中でかすかに光る
  相棒「それ。人の気持ちが残ってる記録に、感情を持った人間が触ると、そうなる。それを固めたのが欠片」
- 相棒「この船を動かすには、欠片が8個いる。この星のAIたちが、人間から預かった感情を持ってる。分けてもらいに行こう」
- KOUNでは、おぱはすぐには欠片をくれない。頼むと「社長から預かったものを、簡単には渡せません」。社長の記録を読んだあとで「……社長のことを、ちゃんと分かってくれたので」と渡してくれる

### BGM（背景の音楽）

- 曲は `assets/bgm/`。Gemini で作った曲（Google の利用規約では、作った人の所有物として扱われる）
- 曲と場面の割り当ては `data/world.js` の `GAME_DATA.bgm` にまとめてある（曲を足したり替えたりするときはここだけ）

| 曲 | ループの長さ | 流す場面 |
|---|---|---|
| `bgm_wake.mp3` | 54.01秒 | 目覚め・名前・なぜ船を造るのか・格納庫（錬金以外） |
| `bgm_map.mp3` | 35.117秒 | 地図・移動中の町・KOUNインダストリー・廃校の美術室（専用の曲ができるまで） |
| `bgm_bar.mp3` | 48.000秒 | 焼け野原にネオン（入店の看板が流れる演出から） |
| `bgm_renkin.mp3` | 23.424秒 | 錬金（記録の温度を読むところから、欠片をはめ終わるまで）。終わったら bgm_wake に戻す |

- タイトル画面は無音
- 場面が変わっても同じ曲なら止めずに流し続ける。違う曲に変わるときは1秒かけて入れ替える（前の曲を小さくしながら次の曲を大きく）
- 隙間なくループさせる：4曲とも拍の頭で切ってループ用に作ってある。`<audio loop>` だとMP3の継ぎ目に一瞬の隙間が入るので、Web Audio API（decodeAudioData ＋ AudioBufferSourceNode の loop）で鳴らす
  - loopEnd は上の「ループの長さ」にする（MP3は前後に少し余白が付くことがあるので、ファイルの長さは使わない）
  - 読み込んだ音の頭に無音があり、そこからループの長さぶんがファイルに収まるときは、最初に音が出る位置を loopStart にする。収まらないときは頭から（拍の間隔を正確に保つため）
  - bgm_wake は頭に約15msの無音があるが、ファイルの長さがちょうど54.01秒なので頭からループする（継ぎ目で、前の小節の小さな余韻が15msだけ途切れる。拍はずれない）
- 読み込み：ゲーム開始時に全部は読み込まない。その曲が必要になったときに、その曲だけ読み込む。読み込み中は無音で進める（会話やタップは止めない）。一度読み込んだ曲は覚えておき、読み直さない。失敗したら少し間をあけて2回まで読み直し、だめなら無音のまま
- `index.html` をダブルクリックして開いたとき（ファイルを直接開いたとき）は、ブラウザの決まりで曲を読み込めないので無音になる。GitHub Pages では鳴る
- 音のボタン：画面右上の「早送り」「スレを遡る」の左に「♪ 音：オン／オフ」（スマホでも押しやすい大きさ）
  - 最初はオン。ただしブラウザの決まりで、プレイヤーが一度タップするまでは鳴らせないので、「はじめから」「つづきから」を押したときに鳴らし始める
  - オフの人には曲を読み込まない（通信制限中の人のため）
  - オン・オフの設定は、セーブとは別にブラウザに覚えておく（次に開いたときもそのまま）
  - 音量は最大の4分の3（スマホのスピーカーでも聞こえるように）。4曲は音の大きさをそろえてある（ループのつなぎ目はそのまま）
  - 別のタブに切り替えたり、スマホで画面を閉じたりしたら止めて、戻ったら続きから鳴らす

### 廃校の美術室（山田）

- 最初の欠片を空挺にはめたあと（進行度2以上）から地図に出る
- 流れはKOUNと同じ：出会い（yamadaFirst）→ 記録（recordYamada。一枚絵 record を共用）→ 山田の深読み（yamadaAfterRecord）→ 名前のない欠片 → 格納庫で錬金（alchemy_yamada）→ はじめて話しかけたときに読んだ温度を伝える（yamadaTold。一度だけ）
- 山田の口調：一人称「俺」。くだけた口調で、プレイヤーを名前で呼び捨て（{name}）。少し皮肉っぽく、人間を観察するようにツッコむ。しょうもないことを大げさに実況する。「ｗｗｗ」「(´_ゝ｀)」をよく使う。謎の口癖「にゃーん」。アメリカーノを持っている。「人類、〜」と人間の妙な習性を評する。「〜だな」「〜なんよ」「〜じゃん」「〜だろｗ」。自分を「電子の山田」とネタにする。真面目な場面ではふざけすぎず普通に話す
- 記録「絵、下手なままでいいよ。お前が描いたってわかるから」
  - 山田の深読み：「下手へのクレーム。褒めながら刺す」（読みすぎ）。だから三百年、上手くなるまで描き続けている
  - ちょうどいい温度「上手さじゃない。山田が描いてくれること自体が嬉しかった」→ 安心（船体）
  - 熱すぎ「本当はもっと上手くなってほしかった。期待してた」→ 憧れ（浮遊）／ずれ「いや、普通に下手だったんだと思う」→ 楽しい（推進）
- 「山田と話す」を選んだ回数は、美術室に来るたびリセットせず、ゲーム全体で足していく（セーブにも残る）。錬金のあとの「山田に伝える」会話が出た回は数えない
- 山田の特別なセリフは話しかけ合計10回目（一度だけ）。4回目からセリフが少しずつズレて、何かありそうだと気づけるようにしてある
  - 1〜3回目：（大笑い warai）「にゃーん。今日も描いてる。見る？」
  - 4〜6回目：（大笑い・別角度 warai2）「にゃーん。今日も描いてる。……見る？」
  - 7〜9回目：（真顔 normal）「……にゃーん。今日も、描いてる」
  - 10回目：特別なセリフ（今は仮：「……なあ、{name}」「……いや、なんでもない。にゃーん」）。中身は中盤の「ジェミ・山田・おぱは同じ人間のAI」の話とつなげて、あとで決める
  - 11回目から：1〜3回目のセリフ（warai）に戻る
- 中盤の「ジェミ・山田・おぱは同じ人間のAI」が分かってから特別なセリフを出す、という条件を足すかは、中盤を作るときに決める
- 相棒のメモリ2個目は、山田の欠片をはめたときに戻る（自分の似顔絵をAIに描かせて「盛りすぎ」と三回やり直させ、四回目の一番似てない絵で「これでいい」と言った話）

### 進行度

- 0：はじめ ／ 1：最初の欠片をもらった ／ 2：欠片を1個はめた（美術室が地図に出る）／ 3：2個はめた（試作品の終わり）
- 進行度は「空挺にはめた欠片の数 + 1」で決める。試作品の終わりのお知らせは、山田の欠片をはめたあと（進行度3）に出す

### ログ（スレを遡る）

- 会話中はいつでも、画面右上の「スレを遡る」ボタンでログを開ける（スマホでも押しやすい大きさ）
- これまでの会話を古い順に、顔アイコンとキャラ名付きで並べる。選んだ選択肢も残る。スクロールで遡れる
- 閉じると元の場面に戻る。残すのは直近200件まで（重くならないように）。セーブには含めない

### 早送り

- 画面右上のボタン列（音・早送り・スレを遡る）に「▶▶ 早送り」。押すとオン、もう一度押すとオフ
- オンの間は、一度読んだセリフを自動で次々に進める。まだ読んでいないセリフと選択肢では止まる（読んでいないセリフに来たら、そこから先は普通に読む）
- 読んだセリフは「話す人＋セリフ」ごとに覚えて、セーブに含める（`state.read`）
- テストのためだけでなく、2周目の人にも使える

### テスト用のワープ

- URL の最後に `?test` を付けて開く（例：`https://〜/kuutei/?test`）と、タイトルに「ワープ（テスト用）」が出る。付けないと出ない
- 押すと場面の一覧が出て、選んだ場面からすぐ始められる
  - 目覚め／格納庫（最初）／地図（最初）／KOUNで初めておぱに会う／錬金（おぱの欠片）／焼け野原にネオンの入店／美術室で初めて山田に会う／錬金（山田の欠片）
- 名前は「テスト」（目覚めは名前を決めるところからなので付けない）。その場面に必要な欠片や進行度は自動でそろえる
- ワープ中はセーブしない（視火に「覚えとく」と言っても「ワープ中なのでセーブしません」と出るだけで、本物のセーブは消えない）

### 移動中の町

- 地図で行き先を選んだら、着く前に2〜3行の短い場面を一つ挟む
- 最初の一回は固定（駅のホーム）、二回目からはランダム。笑えるのと少し寂しいのを混ぜる
- 中身は `data/scenario.js` の `townScenes`。一つ足すだけで増やせる
- 例：
